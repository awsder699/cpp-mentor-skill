# 教学代码规范（Code Style for Teaching）

所有示例、演示、参考代码必须遵守本规范。目标是让代码**成为讲解的一部分**，而不是额外负担。

## 一、基本约束

1. **默认标准 C++17**。用户指定其他版本时从其版本；使用版本相关特性时注明（如 `// C++11 起`、`// C++20 concepts`）。示例应尽量在 GCC / Clang / MSVC 三家主要编译器下均可编译。
2. **最小可运行**：单文件、自包含、`-std=c++17` 可直接编译；不依赖第三方库；不写多文件工程（除非教学主题本身就是多文件/头文件）。
3. **一次一知识点**：示例只演示当前主题。讲指针不混入类，讲 STL 不混入模板进阶。宁可用"稍不真实但极简"的场景。
4. **可复制性**：用户能整段复制进编辑器编译运行；不留 `TODO`、不留占位伪码（半成品骨架除外，见 SKILL.md 第 4 步脚手架 L-C）。

## 二、示例结构模板

```
// 主题：<一句话说明本示例演示什么>
// 预期输出：<先写预期输出，让用户带着预期去跑>

#include <iostream>   // 只 include 真正用到的

int main() {
    // 演示步骤 1：<这一步展示什么现象>
    ...

    // 演示步骤 2：<改了什么，会发生什么>
    ...
    return 0;
}
```

分步展开同一示例时，用「步骤 N：改了什么 → 现在发生什么」的递进结构，每步给出当前完整代码（或明确 diff），不要只描述改动。

## 三、注释规范

- **注释解释"为什么"，不复述代码**。
  - 反例：`x++; // x 加 1`
  - 正例：`x++; // 已处理一个元素，剩余计数减 1`
- 关键行必须注释：易错点、设计意图、版本前提、坑的警示。
- 反例代码中的"错误写法"要显式标注：`// ❌ 错误：...原因`，紧跟 `// ✅ 正确：...`。
- 注释语言：中文（跟随讲解语言）。

## 四、命名与可读性

- 变量名见名知意：教学场景中宁可用 `count`、`totalPrice` 也不用 `c`、`tp`；单字母仅用于 `i`、`j`（循环）、`p`（指针专题演示）等约定俗成场景。
- 一行只做一件事；魔法数字提为具名常量或至少注释。
- 不用炫技写法：不在初学者面前用位运算压缩、链式调用嵌套、三目套三目；现代特性（结构化绑定、`if constexpr`）在相关专题才用，用了要解释。

## 五、输出与验证

- 示例必须给出**预期输出**（用注释或代码块单独列出）。
- 涉及未定义行为（UB）的演示（如悬垂引用、越界）要：① 显式警告；② 建议用户用 `-fsanitize=address,undefined`（GCC/Clang）或 VS 的调试运行亲自验证；③ 说明"输出不确定是正常的，重点是现象背后的原因"。
- 崩溃类演示给出「最小复现 + 修复对照」两份代码。

## 六、调试演示专用

- 教用户读报错：指出报错三要素（错误类型、文件:行号、上下文），示范从最后一行往上读；
- `cout` 调试法示范时，打印要带上下文（`"before loop: x=" << x`），并说明这只是起点，下一步是断点/调试器/sanitizer。

## 七、常见教学示例模式

| 模式 | 用途 | 结构 |
|------|------|------|
| 对比式 | 讲两个易混概念 | 同一场景两份实现并排，差异行高亮注释 |
| 演进式 | 讲设计动机（如为什么需要引用参数） | v1 笨拙写法 → v2 问题暴露 → v3 改进写法 |
| 反例击破式 | 破除迷思 | 先给错误信念的最短代码，展示崩溃/异常输出，再分析 |
| 填空式 | 引导练习 | 关键行留 `// TODO:`，附参考答案于题后 |
| 渐进扩展式 | 课设/项目脚手架 | 最小可运行版 → 每轮加一个功能并说明架构影响 |

## 八、参考代码给分（作业/竞赛题）

仅在用户已尝试（或明确表示放弃）后给出参考代码，且必须：
1. 分块讲解思路与代码的对应关系（先思路后代码，或代码内逐段注释思路）；
2. 标注复杂度与关键不变量；
3. 提醒这不是唯一解，鼓励用户对比自己的写法学可复用之处；
4. 竞赛代码可适度紧凑，但仍保证命名与注释清晰（教学优先于赛场精简）。
