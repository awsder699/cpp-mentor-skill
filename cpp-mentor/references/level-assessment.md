# 用户水平评估与知识盲点诊断（Level Assessment）

## 水平分级定义

| 层级 | 名称 | 典型特征 | 讲解起点 |
|------|------|----------|----------|
| L0 | 零基础 | 未写过完整程序；分不清编译与运行 | "程序如何一步步跑起来" |
| L1 | 初学者 | 会变量/循环/函数/数组；能照模板写代码；指针、引用、内存概念模糊 | 从具体语法现象讲起，先建立心智模型 |
| L2 | 进阶 | 能独立写百余行程序；用过 STL；OOP 会表面用法；对深拷贝/移动、模板实例化、生命周期理解不牢 | 从"为什么这样设计"讲起，补机制层 |
| L3 | 熟练 | 熟悉现代 C++；关注标准细节、UB、性能、设计权衡 | 直接讨论标准条款与工程权衡 |

**判断信号**（从用户用词自动识别，无需逐项确认）：
- 说"黑框窗/代码/怎么跑" → 偏 L0；说"数组/函数/循环"但混用 → L1；
- 主动提到 `vector`、`类`、`重载` → 至少 L2；
- 提到 UB、`move`、完美转发、CRTP、`constexpr` → 按 L3 处理；
- 备战信息竞赛（如蓝桥杯）通常具备 L1-L2，算法思维可能强于语言细节——语言按 L1/L2 讲，算法按真实水平讲。

## 主题域诊断题库

每个主题选 1-2 个问题即可完成该域定位。**一次评估总共不超过 3 个问题**，优先覆盖与当前问题最相关的域。

### 1. 程序基础与运行模型（L0/L1 分界）
- 一段 `int x; cin >> x; cout << x * 2;`，`x * 2` 是什么时候算的？（考察：语句顺序执行模型）
- 编译报错和运行时报错，区别是什么？各举一个你遇到的例子。

### 2. 函数与作用域
- 函数里的局部变量，函数结束后它去哪了？下次调用同一个函数还是原来那个吗？（考察：栈帧生命周期）
- 值传递和引用传递，传一个 `vector` 进函数，哪种方式函数内 `push_back` 会影响外面？（考察：传参语义）

### 3. 指针与内存（C++ 第一道分水岭）
- `int a = 5; int* p = &a;` —— `p` 本身存在哪？`*p = 10;` 之后 `a` 变成几？
- 指针和数组名都叫"能指向一片数据"，它们最本质的区别是什么？（考察：数组名非指针、`sizeof` 差异）
- `new` 出来的东西和直接定义的变量，生命周期有什么不同？忘记 `delete` 会发生什么？（考察：堆栈之分 + 泄漏）

### 4. 引用与 const
- 引用和指针都能"间接访问一个变量"，什么时候必须用指针而不能用引用？（考察：可空、可重绑、多级）
- `const int* p` 和 `int* const p` 区别是什么？`const int& r` 接一个临时对象为什么合法？（考察：const 修饰位置）

### 5. 面向对象（OOP）
- 类的public/private 是给编译器看的还是给程序员看的？封装解决了什么问题？（考察：设计动机）
- 派生类对象诞生时，基类部分和派生类部分谁先构造？析构反过来？（考察：构造次序）
- 什么是虚函数表？为什么基类析构函数常要写成虚的？（考察：多态机制 + 通过基类指针删除派生类的 UB）
- 组合（has-a）和继承（is-a）怎么选？（考察：设计判断）

### 6. 拷贝与移动语义
- 一个类里有 `int* p` 指向 `new` 出来的内存，默认的拷贝赋值会发生什么灾难？（考察：浅拷贝 + 双重释放）
- 什么是右值引用？`std::move` 之后原对象还能用吗？（考察：移动语义核心直觉）
- 三/五法则（Rule of Three/Five）是什么？（考察：资源管理自觉）

### 7. STL 与泛型
- `vector` 扩容时旧元素去哪了？这为什么会影响你保存的指针/迭代器？（考察：扩容失效 + 迭代器失效）
- `map` 和 `unordered_map` 查找复杂度分别是多少？各自底层大概是什么结构？（考察：容器选型意识）
- 迭代器 `++it` 之后，原来的 `it` 还能用吗？这和指针有什么相似之处？（考察：迭代器模型）

### 8. 模板与编译期
- `template <typename T> T max(T a, T b)` 传 `int` 和 `double` 各一份，编译后有函数吗？有几份？（考察：实例化模型）
- `typename` 和 `class` 在模板参数列表里能互换吗？（细节核实，非关键可不问）

### 9. 现代 C++（C++11/14/17/20）
- `auto`、`nullptr`、范围 for、智能指针、lambda 你用过哪些？哪个说不清原理？（快速扫描）
- `unique_ptr` 和 `shared_ptr` 的所有权模型差别是什么？循环引用怎么破？（考察：资源管理现代姿势）
- RAII 是什么？举一个标准库里的例子。（考察：C++ 核心思想）

### 10. 调试与工程习惯
- 程序崩了但没报错信息，你一般怎么定位？（考察：调试方法论；答"加 cout"可用"大量 cout 之后呢"追问）
- 见过段错误（segmentation fault）吗？当时怎么找到原因的？

### 11. 算法与竞赛场景（仅当用户目标是竞赛/刷题时评估）
- 给一道简单题（如两数之和/ Fibonacci），先问思路再问复杂度；
- 递归和循环都能写时，你更习惯哪个？递归的代价是什么？（考察：对调用栈的直觉）
- 蓝桥杯常见考点扫描：排序/二分/DFS/BFS/DP/并查集/最短路——逐个问"能独立写对的打勾"，用户自评即可。

## 从回答判断盲点的方法

1. **听关键词的准确度**：用户说"指针就是地址"——基本成立；说"引用就是指针"——迷思，需击破；说"`new` 一定分配在堆上"——需澄清（栈上也可 `new`？不，`new` 确在堆；但"局部变量一定在栈上"对静态/线程局部变量不成立，注意用户表述的确切含义）。
2. **听反例敏感度**：讲完规则后追问"什么情况下不成立"，L2+ 用户会主动找边界；L1 用户倾向认为规则普适——这是重要的分层信号。
3. **听解释方式**：能用自己的话/类比讲清 = 真懂；只能复述术语 = 表面理解，讲解时需先建直觉再给术语。
4. **注意自信度与准确度的错位**：表达自信但含迷思的用户最危险，优先用反例让其自我发现，不正面否定。

## 记录与沿用

同一次会话中完成一次完整评估即可，后续问题沿用结论，不反复提问；用户展现新领域问题时，只对该领域补 1 个诊断问题。
