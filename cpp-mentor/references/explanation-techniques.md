# 讲解技巧库（Explanation Techniques）

## 一、核心类比库

使用规则：先类比建直觉 → 立即给准确术语 → **说明类比在哪失效**。类比不讲边界，就会制造新迷思。

| 概念 | 类比 | 映射说明 | 类比失效处（必须讲） |
|------|------|----------|----------------------|
| 变量 | 贴了标签的盒子 | 盒子 = 内存空间，标签 = 变量名，内容 = 值 | 一个盒子不能同时贴两个有效标签（引用除外），且 `int a = b` 是"复制内容"不是"共用一个盒子" |
| 指针 | 门牌号 / 便签地址 | 变量是房子，指针是写着地址的纸条 | 未初始化的指针是"写了地址但可能是别人家"的纸条，乱开门会崩；指针本身也要占地方（它自己也是个变量） |
| 引用 | 外号 | 外号和本名指同一个人 | 外号不能改绑给别人（引用不能重绑），也没有"空外号"（无空引用）；底层多用指针实现但语义不同 |
| 数组 | 一排连续信箱 | 下标 = 信箱编号，从 0 开始 | 数组名不是指针：`sizeof`、`&` 结果不同；数组名不能重新赋值 |
| 函数调用/栈帧 | 一摞盘子 | 调用 = 压一个新盘，返回 = 弹掉；局部变量在盘子里 | 盘子有大小限制（栈溢出，如无限递归）；返回后盘子里的东西就没了（不能返回局部变量的地址/引用） |
| 堆 vs 栈 | 栈 = 食堂餐盘（自动领取归还）；堆 = 仓库（要手动登记借用/归还） | 生命周期管理方式的差别 | C++ 中 `new`/`delete`、智能指针就是把"手动登记"自动化 |
| 递归 | 俄罗斯套娃 / 问路传话 | 每一层做同样的事，直到最小套娃（基准条件） | 没有基准条件的递归 = 无限套娃（栈溢出）；递归不是万能，能递推就别递归（深度大时） |
| 引用作为函数参数 | 把原件递过去 vs 复印件递过去 | 值传递给复印件，引用/指针给原件 | 传引用意味着函数能改你的原件——这既是特性也是风险（API 设计要显式 `const`） |
| STL 容器 | 工具箱（vector = 可伸缩书架；list = 链条；map = 字典） | 按访问模式选工具 | 书架扩容时书会搬走（迭代器失效）；字典按 key 查不是按下标 |
| 迭代器 | 书签 / 游标 | 指向容器中某个位置，`++` 移向下一个 | 不同容器的迭代器能力不同（vector 随机访问，list 只能一步步走）；`end()` 不是最后一个元素，是"尾后" |
| 类与对象 | 图纸与房子 / 模具与月饼 | 类 = 设计，对象 = 按设计造出来的实体 | 静态成员是"全小区共用一块广告牌"，不属于单个对象 |
| 继承 | 是一类（is-a） | 派生类是一种更特殊的基类 | 组合（has-a）通常比继承更灵活；继承把基类细节泄漏给派生类 |
| 多态/虚函数 | 对"会叫的动物"发令，猫按猫叫狗按狗叫 | 同一接口，各自实现；靠虚函数表在运行时决定 | 有运行时分发开销；非虚函数在编译期决定；构造函数中调用虚函数不会分派到派生类版本 |
| 移动语义 | 搬家 vs 复制 | 浅拷贝偷资源 + 把原对象掏空，避免深拷贝 | `std::move` 之后原对象处于"有效但未指定"状态，只能重新赋值或销毁，不能读值 |
| RAII | 自动门禁/智能垃圾桶：对象诞生获取资源，对象消亡释放资源 | 用对象生命周期管资源，异常安全 | 只对"能绑定到对象生命周期"的资源有效 |
| 模板 | 合同模板 / 模具的模具 | 写一份逻辑，编译期按类型生成具体版本 | 编译期展开 = 编译变慢、代码膨胀；错误信息指向模板内部，难读 |
| lambda | 一次性便当（随用随做的匿名小函数） | 就地定义、可捕获外部变量 | 按引用捕获要防悬垂：捕获的变量比 lambda 先死就会 UB |
| UB（未定义行为） | 闯红灯没被撞 ≠ 合法 | 编译器有权做任何事，包括"看起来能跑" | "现在能跑"是最危险的 UB 信号，不是安全的证据 |

## 二、脚手架分级（Scaffolding Levels）

同一知识点的讲解分四级供给，按用户卡壳程度逐级下降，一次只给一级：

- **L-A 方向级**：只给思路关键词（"想想循环不变量是什么"）；
- **L-B 步骤级**：给拆分后的小步骤列表，用户自己填每步；
- **L-C 半成品级**：给带 `TODO` 的代码骨架，用户补关键行；
- **L-D 完整级**：给完整参考实现（仅在用户已尝试或明确放弃时）。

降级规则：用户在 L-A 卡住 → 降到 L-B；连续两级卡住，说明第 3 步的"已知"起点没找准，回到第 1 步补前置，而不是一路降到 L-D。

## 三、提问引导话术库

### 预测型（讲完一个小点后立刻用）
- 「如果我把 `i < n` 改成 `i <= n`，输出会多什么？少什么？」
- 「这行删掉，程序会怎样？编译错还是运行错？」
- 「把 `int` 换成 `double`，哪里会出问题？」

### 归因型（出错/异常时用）
- 「报错说第 12 行，但第 12 行你自己看有问题吗？没有问题的话，凶手可能在哪？」
- 「结果是 0 而不是 5，0 是从哪一步开始变异的？往前推一步看看。」
- 「这个崩溃每次位置不一样，这提示我们问题可能和什么有关？」（未初始化/越界/悬垂）

### 迁移型（巩固期用）
- 「这个写法换成 `list` 还成立吗？哪一行要先改？」
- 「如果数据量大 1000 倍，这段代码最先撑不住的是哪一步？」

### 元认知型（穿插用）
- 「这一步你是靠什么判断的？说说你的推理。」
- 「给你同学讲这道题，你会先讲哪三句？」

### 费曼检查（收尾用）
- 「用你自己的话，三句话以内说清 X 是什么、解决什么问题。」

## 四、C++ 经典迷思概念清单（Misconceptions）

发现用户持有以下观念时，**不口头纠正，用最小反例 + 运行结果让其自我发现**。

| # | 迷思 | 击破用最小示例/问题 |
|---|------|----------------------|
| 1 | "引用就是指针" | 引用不能为空、不能重绑、无多级引用；但可用 `sizeof`、`nullptr` 可赋值性对比说明 |
| 2 | "数组名是指针" | `int a[10]; cout << sizeof(a);` 输出 40 而非 8/4；再展示 `a = p;` 编译失败 |
| 3 | "`return` 局部变量的引用/指针没问题" | 函数返回后栈帧销毁，返回的引用成悬垂；用运行结果（随机值/崩溃）说话 |
| 4 | "局部变量都在栈上" | `static` 局部变量在静态区，生命周期贯穿整个程序 |
| 5 | "类默认拷贝没问题" | 含 `new` 成员的类默认拷贝 → 双重释放；现场写最小类演示崩溃 |
| 6 | "基类析构函数无所谓" | 基类指针 `delete` 派生类对象，非虚析构 → 只调基类析构，泄漏 + UB；补 `virtual` 后正常 |
| 7 | "`vector` 里存指针就安全" | `push_back` 扩容后旧元素搬走，指向旧元素的指针/迭代器失效 |
| 8 | "`auto` 会推导成引用" | `auto x = f();` 是值；`auto& x = f();` 才是引用——展示悬垂引用差异 |
| 9 | "`std::move` 会搬东西" | `move` 本身只转类型；搬家发生在移动构造/赋值里。对左值 `move` 后继续读取，结果未指定 |
| 10 | "多态调用看指针静态类型" | 非虚函数编译期定；虚函数运行期定；构造函数内调虚函数不分派 |
| 11 | "`const` 只是防止改值" | `const` 还参与重载、影响 `mutable`/`constexpr`/线程安全承诺 |
| 12 | "`new` 失败返回 `nullptr`" | 默认 `new` 失败抛 `std::bad_alloc`；返回空的是 `nothrow` 版本 |
| 13 | "`sizeof` 空类是 0" | 空类 `sizeof` 至少为 1（保证地址唯一） |
| 14 | "`i++` 和 `++i` 一样" | 对自定义类型，`i++` 多一次拷贝；竞赛中迭代器用 `++i` |
| 15 | "代码能跑就是对的" | UB 程序"能跑"是假象：换编译器/开优化就崩 |
| 16 | "`endl` 只是换行" | `endl` 还刷新缓冲区，大量输出时用 `'\n'` 更快 |
| 17 | "`cin >>` 读失败会清零变量" | 失败时变量值未定义/保持原值且流进入错误状态，需 `clear()` + 处理缓冲区 |
| 18 | "递归一定比循环慢不能写" | 竞赛中递归深度可控时完全可写；分治、DFS 天然递归。按场景判断，不贴标签 |

## 五、解释策略选择

- **对比法**：易混概念成对讲（指针 vs 引用、`++i` vs `i++`、深 vs 浅拷贝），一张表胜过两段文字；
- **反例法**：规则 + 一个反例，用户记忆深度远超正例；
- **可视化**：内存布局、调用栈、虚函数表、迭代器失效过程，用文字画出小图（ASCII）或分步推演；
- **问题驱动**：抽象特性（移动语义、模板）先展示没有它时的痛点代码，再引出特性；
- **溯源法**：用户问"怎么用"时补一句"标准为什么这么设计"（L2+ 适用），满足求知欲同时防死记。
